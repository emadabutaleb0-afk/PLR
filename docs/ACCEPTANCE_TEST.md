# اختبار القبول مع الشرنوبي (45 دقيقة)

**الهدف:** نتأكد إن مسؤول من الشركة يقدر يمشي في سيناريو قرار كامل لوحده، وإن الأرقام والصلاحيات مفهومة ومقبولة عنده.
**ممنوع في الاختبار ده:** أي نتيجة تتقال على إنها "وفر" أو "ربح محقق". كل الأرقام تقديرات على بيانات تدريبية مجهولة إلا لو الشركة أكدت غير كده.

## قبل ما نبدأ (10 دقايق، على الجهاز اللي هيتسلم)
1. `python ops/gen_env.py --admin-email <إيميل حقيقي>` ثم `python ops/preflight.py` (لازم تطلع `0 blockers`).
2. حطوا الـ 20 ملف CSV في `data/private/` (أو الملفات الحقيقية المحدثة) وشغلوا `run-windows.bat`.
3. اتأكدوا إن صفحة **Data Health** مفيهاش `FAILED`، وإن تاريخ آخر داتا ظاهر.
4. اطلعوا **GET /data/reconciliation** (أو زر الفحص لو اتضاف) وسجلوا الـ WARN اللي ظاهرين، وناقشوها مع مسؤول المالية.

> الخطوة 7 مش هتتم فعليًا قبل ما تجي داتا جديدة بعد تاريخ التنفيذ. في يوم الاختبار نعمل الخطوات 1 لـ 6 ونسجل إن القياس مؤجل.

## صلاحيات (10 دقايق): جربوا بحساب لكل دور
- Store Manager: بيشوف مواقعه بس، ومبيشوفش الموردين ولا الخطط.
- Marketing Manager: مبيشوفش التكاليف ولا المشتريات.
- Analyst: بيشوف كل حاجة لكن مبيعتمدش قرارات.
تأكدوا إن اللي بيظهر لكل دور هو اللي الشركة عايزاه فعلًا.

## قرارات لازم الشرنوبي يحددها (تتحط في الإعدادات)
| الإعداد | القيمة الحالية | مين يحدد |
|---|---|---|
| `MAX_ACTIONS_PER_DEPARTMENT` (كام قرار القسم يقدر ينفذ في الأسبوع/الخطة) | 8 (افتراض) |  |
| `DECISION_BUDGET_EGP` (سقف المشتريات في الخطة) | بدون سقف |  |
| `TRANSFER_COST_PER_UNIT_EGP` (تكلفة نقل القطعة بين المواقع) | 0 (غير متاحة في الداتا) |  |
| `STALE_DATA_DAYS` (بعد كام يوم الداتا تعتبر قديمة وتمنع الموافقة) | 45 |  |
| معدل تحديث الداتا (يوميًا / أسبوعيًا) لكل ملف | غير محدد |  |
| هل الداتا الحالية حقيقية ولا تدريبية؟ | تدريبية/مجهولة حسب الملفات |  |

## معيار النجاح
- المستخدم أنهى الخطوات 1 لـ 6 بدون مساعدة وبدون ما يوصل لشاشة خطأ.
- أي رقم اتناقش اتقال عنه "تقدير" مش "وفر".
- لا يوجد أسرار أو بيانات الشركة في أي نسخة خرجت برا الجهاز (راجعوا ZIP التسليم).
- الاعتراضات كلها اتسجلت في الجدول فوق بدل ما تتنسي.
